## Roadmap

### 1. Live link

Deploy the site on Vercel so it has a public link. You’ve already done this. **Done when** the site opens on a public link.

### 2. Richer project data

Add role, year, tools, problem, process, result and images to `projects.js`. Then update the case-study page to show them. **Done when** each project page shows its own details instead of generic text.

### 3. Real content

Write the text and export the images for at least 3 projects. Fill in the Home and About pages too. This runs alongside steps 2 and 4. **Done when** no placeholder text is left on the pages you’ll show people.

### 4. Motion

Add three effects only: hover effects, scroll reveal and glitch text on the hero. All three must turn off for people who choose “reduce motion”. **Done when** they run smoothly on your laptop and stop when reduce motion is on.

### 5. Contact form

Build the fields, labels and validation. Then send the form to a form service. Show loading, success and error messages. **Done when** a test message reaches your inbox.

### 6. Polish and v1 release

Compress the images, check the site on a phone and run Lighthouse. Write the README and tag the release `v1.0`. **Done when** the site is live, Lighthouse scores 90 or higher, and the README is finished.

### Rest period

Take a break during exams. Do light work only. **Done when** your exams are over. Nothing else is required.

### 7. Move to Next.js and TypeScript

Move one page at a time, starting with the Work grid. **Done when** the whole site runs in Next.js.

### 8. Add Three.js

Add a 3D object to the Home hero. **Done when** the 3D scene runs smoothly.

### Rules to keep

- Skip page transitions.
- Stop at three effects.
- Move to Next.js only when v1 is live and tagged.
- If you fall behind, drop the glitch text first, then slim the content. Never drop the live link or the contact form
